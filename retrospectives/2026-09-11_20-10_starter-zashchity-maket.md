# Ретро: стартер 1.1.0, защиты и макет первой версии

**Дата:** 2026-09-11 20:10
**Длительность:** ~1,5 часа
**План:** просьба владельца в чате; канонический чертёж - `architecture/README.md`

## 1. Задача

Дополнить проект новой версией claude-code-starter без затирания своих файлов, адаптировать проверки и защиту от секретов к стеку, связать правила с чертежом. По замыслу и плану сделать локальный интерактивный макет первого сквозного сценария.

## 2. Как решал

- Склонировал стартер во временную папку, прочитал README, `install.py`, `check_secrets.py`, тесты. Установщик по умолчанию только показывает план (dry-run), пишет лишь ссылки и недостающие шаблоны. Settings, hooks и git он не трогает.
- Запустил установщик с `--agent claude`: `.starter/workflow.md`, управляемый блок в `CLAUDE.md`, `/.business/` в конце `.gitignore`. Остальное объединил руками.
- Сканер секретов дополнил под стек: URL базы с паролем, JWT (WB), ключи Yandex Cloud. Код вида `process.env.X` находкой не считается. Добавил приватные пути. Hook Claude Code `.claude/hooks/guard.mjs` написал на Node - это язык стека.
- Проверки: 19 тестов сканера на Python 3.14 и 3.8, 6 тестов hook-а, реальные коммиты в одноразовом клоне, запуск hook-а командой из `settings.json`.
- Макет - `mockups/v1-scenariy-1/index.html`, в стиле прототипа каталога: 6 шагов, у каждого 5 состояний.

## 3. Решил?

- [x] Частично. Всё сделано и проверено, кроме живого срабатывания hook-а внутри новой сессии Claude Code: консольный `claude` не залогинен, проверить можно только в новой сессии.

## 4. Что можно было лучше

- В тестах сканера сами фикстуры дважды выглядели как секрет (`config.payments.` с точкой, ключ словаря `'...password': '...'`). Фикстуры надо собирать так, чтобы исходник теста не совпадал с шаблонами.
- `grep -c $'\r$'` в Git Bash на этой машине врёт. Окончания строк проверять через Python (подсчёт байтов).
- Установщик стартера не переживает `core.autocrlf=true`: контрольная сумма блока ломается. Закрепил LF в `.gitattributes`.

## 5. Как было / как стало

- **Было:** стартер старой версии, `security-audit.sh` проверял сам шаблон, pre-commit не установлен, в правилах разрешалось читать `.env` через `grep`.
- **Стало:** общий процесс 1.1.0 со ссылкой из `CLAUDE.md`, порядок источников при конфликте, таблица автоматических проверок, работающие pre-commit и hook, макет сценария «промокод → заказ → канал».
