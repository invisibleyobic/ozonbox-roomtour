# OzoneBox - навигация по проекту

Новый сайт магазина лечебной озоновой косметики ozonbox.ru вместо Tilda: скролл-тур по каталогу, SEO-страницы под Яндекс, своя корзина и оплата.

Подробности - в `.business/INDEX.md`.

## Структура репозитория

```
ozonbox-roomtour/
├── CLAUDE.md                ← этот файл, правила работы
├── TROUBLESHOOTING.md       ← решения типовых проблем Claude Code
├── .business/               ← скрытая папка, бизнес-контекст (не в git)
├── .starter/workflow.md     ← общий процесс claude-code-starter 1.1.0 (не править руками)
├── .claude/                 ← настройки и защитный hook Claude Code (hooks/guard.mjs)
├── idea/                    ← замысел (эфир 2): superidea → pitch
├── architecture/            ← чертёж (эфир 3): правила, сущности, база, стек, план
├── mockups/                 ← макеты-имитации (не код продукта)
├── plans/                   ← технические планы отдельных задач
├── retrospectives/          ← рефлексии после каждой сессии
├── scripts/                 ← проверка секретов и аудит безопасности
└── prompts/                 ← библиотека готовых промптов
```

## Чертёж, правила и общий процесс

**Порядок источников при конфликте:** 1) прямое решение владельца в чате; 2) `architecture/00-правила-проекта.md` (всегда / спроси / запрещено); 3) чертёж `architecture/README.md` и его файлы; 4) этот файл; 5) общий процесс стартера `.starter/workflow.md`.

- Код пишется только по чертежу `architecture/README.md`. Задача противоречит чертежу - остановиться и спросить.
- Замысел - `idea/`, начинать с `idea/pitch.md`. Бизнес-контекст - `.business/INDEX.md`.
- Макет первой версии - `mockups/v1-scenariy-1/index.html`. Это имитация, а не работающий код.
- Чем этот проект отличается от `.starter/workflow.md`:
  - шаги Смыслокода идут по одному: один шаг = один файл = один промпт, с подтверждением владельца. Автономно проходить все фазы без вопроса «продолжать?» можно только после отдельного одобрения плана;
  - интервью заново не проводим: контекст уже лежит в `idea/`, `architecture/` и `.business/`;
  - независимое ревью и «судья» проводятся в отдельной сессии. Если ревью не было, так и пишем.

## Какие правила проверяются автоматически

| Правило | Чем проверяется |
|---|---|
| Секреты (`.env`, ключи) не читаем и не правим | hook `.claude/hooks/guard.mjs` + `deny` в `.claude/settings.json` |
| В git только поимённо, без `--no-verify` и `commit -a` | hook `guard.mjs` |
| Секреты и `.business/` не попадают в коммит | `.git/hooks/pre-commit` → `scripts/check_secrets.py --staged` |
| Базу не сбрасываем, данные не удаляем | hook `guard.mjs` (`prisma migrate reset`, `db push --force-reset`, `DROP`/`TRUNCATE`, `DELETE` без `WHERE`) |
| `idea/`, `architecture/`, `.business/`, `.git` не удаляем | hook `guard.mjs` |
| Режим обхода разрешений не включаем | hook `guard.mjs` |
| `git push` - только с подтверждением | `ask` в `.claude/settings.json` |
| Всё вместе, перед push | `bash scripts/security-audit.sh` |

Остальные правила из `00-правила-проекта.md` (источник у заказа, копейки, бюджет скорости, медицинские обещания) пока проверяются только чтением: автоматические проверки появятся вместе с кодом. Hook - это страховка от ошибок агента, а не граница безопасности: скрипт на другом языке его обойдёт.

## Стек

Next.js + TypeScript, GSAP + ScrollTrigger (Club-плагины ScrollSmoother и SplitText - локально из `C:/Users/user/Downloads/gsap-public/`, не с CDN), видео-скраббинг вместо 3D. Окончательный выбор - `architecture/05-стек.md`.

## Ключевые принципы работы

1. **Всегда читай `.business/INDEX.md`** перед задачей, связанной с бизнесом.
2. **Один чат - одна задача.** Разные задачи = разные чаты.
3. **Ищи в `prompts/INDEX.md` до того как писать промпт с нуля.**
4. **План для каждой новой функции** - в `plans/YYYY-MM-DD-название.md`:
   - Фазы со статусами `[ ]` / `[x]`
   - Итоговый блок: реализовано / что осталось
   - Актуализация плана после каждой сессии
5. **Ретроспектива в конце каждой сессии** - в `retrospectives/YYYY-MM-DD_HH-MM_название.md`.
6. **Перед push** - запусти билд и линтер своего стека.
7. **Коммить только свои изменения.** Никаких `git add .` - файлы поименно.
8. **Данные с коротким TTL** - в БД/конфиге, не в коде (цены, остатки, тарифы доставки).
9. **Текст никогда не вшиваем в видео** - заголовки, цены и кнопки только HTML поверх.

## Безопасность

- Не скармливай Клоду паспорта, пароли, ПДн клиентов, ключи.
- `.env` не читаем ни целиком, ни выборочно: значения не должны попадать в чат. Проверить, что переменная задана: `grep -c '^ИМЯ=' .env` (выводит число, не значение). *Уточнено 11.09.2026: раньше разрешался `grep` по переменной, но он печатает значение.*
- Режим Bypass Permissions не включаем - ни глобально, ни в настройках проекта (решение 11.09.2026). Разовый обход - только по отдельному решению владельца, после git-коммита и в изолированной среде.
- Перед установкой любого скила / MCP - аудит через `prompts/setup/08-skills-install.md`.

## Триггеры операционного планирования

| Фраза | Действие |
|---|---|
| «давай спланируем неделю» | `.business/goals/monthly.md` → создай `.business/execution/YYYY-WNN.md` |
| «добавь задачу» | В файл текущей недели или в `.business/execution/backlog.md` |
| «итоги недели» | Заполни секцию «Итог недели» |
