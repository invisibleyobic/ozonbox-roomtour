# Регламент: работа агента в репозитории

Правила безопасности и порядка при любой работе с кодом.

## Секреты

- `.env` и любые файлы с ключами никогда не коммитятся и не читаются
  целиком. Нужна одна переменная - достаём строкой
  (`grep "^ИМЯ=" .env`), без показа значения в чате.
- Ключи, токены, пароли не печатаются ни в лог, ни в отчёт, ни в код.
  В логах - максимум префикс.
- Нашёл секрет в коде или в истории git - не удаляй молча, скажи человеку:
  ключ надо отозвать и перевыпустить, а не просто стереть строку.

## Коммиты и публикация

- Перед push - сборка проекта (`npm run build` или аналог). Не собралось -
  не пушим.
- Коммит - атомарный: одно изменение, понятное сообщение.
- Пуш и деплой - только по явной команде человека, если не договорились
  иначе в начале работы.
- Временные скрипты, одноразовые endpoint'ы, отладочные файлы - удаляются
  после использования, а не оседают в репозитории.

## Данные людей (PII)

- Email, телефоны, реквизиты, содержимое переписок пользователей не
  показываем в чате и не тащим в код/тесты. Маскируем: `i***@g***`.
- Выгрузки из базы - только по явной просьбе и в файл, не в чат.

## Деструктивные действия

- Удаление данных, откат миграций, смена прав доступа, возвраты денег -
  сначала описать человеку ЧТО случится, получить «да», потом делать.
- После мутации всегда read-back: прочитать объект заново и сверить,
  что состояние совпадает с ожиданием.

## Ошибки

- Команда упала - читать ошибку целиком, а не перезапускать вслепую.
- Не получилось три раза подряд одним способом - остановиться и сказать
  человеку, что упёрся, вместо четвёртой попытки.

## Атрибуты data-* в общем коде (выучено 15.10.2026)

**Правило.** Новый `data-*` атрибут для кнопок не должен совпадать с уже занятым в общем скрипте (`shop.js`). Перед тем как назвать атрибут, грепни его по всему скрипту. Данные из браузера (корзина в `localStorage`) при загрузке проверяем: в корзине только коды товаров из каталога и целые количества больше нуля.

**Почему.** В главной 10 кнопки-подсказки поиска («Масло», «Лицо») получили `data-q`, а этим же атрибутом корзина помечает кнопки «+/−». Нажатие «Масло» добавило в корзину несуществующий товар, счётчик показал NaN и запомнился в браузере. Владелец заметил это сам.

**Как применять.**
1. Новый атрибут - префикс по блоку: `data-sq` для поиска, `data-ex-*` для окна «Стойте!».
2. `grep -n 'data-ИМЯ\|dataset.ИМЯ' shop.js` до того, как писать код.
3. После любой новой кнопки в тесте Playwright: нажать её и проверить, что счётчик корзины остался числом.
