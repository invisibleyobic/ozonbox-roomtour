# Чертёж OzoneBox

Claude пишет код только по этому чертежу. Если задача противоречит чертежу - остановиться и спросить. Замысел, на который опирается чертёж, лежит в `idea/`, начинать с `idea/pitch.md`.

## Оглавление

- `00-правила-проекта.md` - нерушимые правила: всегда / спроси / запрещено
- `01-что-строим.md` - продукт простыми словами и границы первой версии
- `02-сущности.md` - общий словарь главных вещей продукта и связей
- `03-база-данных.md` - таблицы, индексы, правила целостности, миграции
- `schema.prisma` - готовая схема базы, первая миграция на эфире 4
- `04-потоки-данных.md` - что человек видит сразу, что уходит в фон
- `05-стек.md` - технологии и почему именно они
- `06-внешние-сервисы.md` - оплата, уведомления, хранилище, MCP, дневные потолки
- `07-безопасность.md` - персональные данные, защита, расходы, роли
- `08-структура-кода.md` - модули, папки, переходники, карта владения окнами
- `09-риски.md` - премортем архитектуры
- `10-план-реализации.md` - план по неделям и промпт на эфир 4

## Как чертёж связан с правилами работы

- `CLAUDE.md` в корне - вход для Claude. Он ссылается сюда как на единственный чертёж и задаёт порядок источников при конфликте. На первом месте решение владельца, дальше `00-правила-проекта.md`, этот чертёж и общий процесс стартера `.starter/workflow.md`.
- `00-правила-проекта.md` - нерушимые правила. Часть из них уже проверяет автоматика: hook `.claude/hooks/guard.mjs` (секреты, git поимённо, сброс базы, обход разрешений) и проверка секретов при коммите `scripts/check_secrets.py`. Полный список - в `CLAUDE.md`, раздел «Какие правила проверяются автоматически».
- `10-план-реализации.md` - единый план первой версии. Второй план в `plans/` не заводим, `plans/` - для отдельных задач со ссылкой сюда.
- Макет первого сквозного сценария «промокод → заказ → видно канал» лежит в `../mockups/v1-scenariy-1/index.html`. Это имитация по `idea/mvp.md` и `idea/proof-of-value.md`. Шаги 1-10 чертежа пока черновики, поэтому всё, чего нет в замысле, помечено в макете как предложение.

## Текущий шаг

- **Готово:** шаг 0 - каркас, `00-правила-проекта.md`, `.gitignore`, `.env.example`. Замысел `idea/` собран целиком (10 файлов).
- **Следующий:** шаг 1 - `01-что-строим.md`, по промптам инструкции дня 3 (`X:/Смыслокод/Эфир 3/`). Затем шаги 2-10 по одному файлу.
- **Решения, которые уже приняты:**
  - MVP - 19 товаров, одна осенняя сцена, корзина с промокодом, CloudPayments, заказы в базе в РФ, сообщение в Telegram;
  - запуск на тестовом поддомене до SEO-переезда;
  - стек - Next.js + GSAP с видео-скраббингом, окончательно на шаге 5;
  - порог - оплаченные заказы с промокодами до 31.10.2026;
  - **промокод (11.09, решение 1А по макету):** один код на ролик, многоразовый, с лимитом использований и сроком действия. В директ всем уходит одинаковый текст. Уникальные одноразовые коды - позже, остальное менять не придётся;
  - **Telegram (11.09, решение 2А):** бот пишет только об оплаченных заказах и только после подтверждения CloudPayments: номер, сумма, состав, код, канал, без личных данных. Неоплаченные и брошенные заказы видны только в базе;
  - **неверный код (11.09, решение 3А):** не найден, истёк, исчерпан или нет связи - покупку не блокируем. Показываем причину и даём оплатить без выгоды. Источник берём из utm-меток ссылки, иначе `unknown`, и такой заказ помечается в отчёте как проблема.
- **Открыто (спросить у владельца проекта):**
  - размер выгоды по коду (процент, рубли или подарок) - решает Рафаэль;
  - что выдавать, когда лимит кода ролика исчерпан (код другого ролика искажает картину каналов);
  - кто и откуда отгружает заказы с сайта, тарифы доставки вне центра;
  - критерий успеха Рафаэля;
  - точка отсчёта по заказам;
  - ссылка на Telegram-канал;
  - ставить ли регламенты github.com/artemiimillier/rules (16 КБ);
  - токен Telegram-бота - вводит сам через `/telegram:configure`.
