# Чертёж OzoneBox

Claude пишет код только по этому чертежу. Если задача противоречит чертежу - остановиться и спросить. Замысел, на который опирается чертёж, лежит в `idea/`, начинать с `idea/pitch.md`.

- `00-правила-проекта.md` - нерушимые правила: всегда / спроси / запрещено
- `01-что-строим.md` - продукт простыми словами, границы первой версии, признак готовности и требования к работе ✅
- `02-сущности.md` - общий словарь главных вещей продукта и связей ✅
- `03-база-данных.md` - таблицы, индексы, правила целостности, файловое хранилище, миграции ✅
- `schema.prisma` - готовая схема базы (PostgreSQL + Prisma), первая миграция на эфире 4 ✅
- `04-потоки-данных.md` - события продукта, что человек видит сразу, что уходит в фон, очередь задач ✅
- `05-стек.md` - технологии, цены и почему именно они ✅
- `06-внешние-сервисы.md` - оплата, чеки, уведомления, хранилище, статистика, сменные прослойки, дневные потолки, MCP ✅

## Как чертёж связан с правилами работы

- `CLAUDE.md` в корне - вход для Claude. Он ссылается сюда как на единственный чертёж и задаёт порядок источников при конфликте. На первом месте решение владельца, дальше `00-правила-проекта.md`, этот чертёж и общий процесс стартера `.starter/workflow.md`.
- `00-правила-проекта.md` - нерушимые правила. Часть из них уже проверяет автоматика: hook `.claude/hooks/guard.mjs` (секреты, git поимённо, сброс базы, обход разрешений) и проверка секретов при коммите `scripts/check_secrets.py`. Полный список - в `CLAUDE.md`, раздел «Какие правила проверяются автоматически».
- `10-план-реализации.md` - единый план первой версии. Второй план в `plans/` не заводим, `plans/` - для отдельных задач со ссылкой сюда.
- Макет первого сквозного сценария «промокод → заказ → видно канал» лежит в `../mockups/v1-scenariy-1/index.html`. Это имитация по `idea/mvp.md` и `idea/proof-of-value.md`. Шаги 1-10 чертежа пока черновики, поэтому всё, чего нет в замысле, помечено в макете как предложение.

FOR UPDATE SKIP LOCKED`), задача пишется той же транзакцией, что и отметка «оплачен». Пять состояний задачи: принято, в работе, готово, ошибка-повторим, сдалась. Принятые развилки: вебхук основной, опрос CloudPayments - страховка для заказов, зависших дольше 15 минут; браузеру не верим, оплаченным заказ делает только подписанный вебхук; повторное оформление закрывается ключом идемпотентности с уникальным индексом; против двойного списания пять слоёв, два из них - уникальные индексы базы; большие файлы - в объектном хранилище в РФ через CDN и готовятся до выката, покупатель файлов не ждёт; источник живёт в cookie первой стороны 30 дней, первое касание не перетирается; истёкший или исчерпанный код всё равно записывается источником заказа с нулевой выгодой.
